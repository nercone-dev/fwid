# FWID (FourWord Identifier)
時系列でソート可能な、新しいランダム識別子の生成方式

## 概要
ランダムな識別子を生成するための新しい方式です。
データベースの主キーなどの用途を想定して設計されています。

長さは可変であり、必要に応じて変更できます。
2026-11-04時点では192bitが推奨される長さとなっています。

衝突の可能性を最小限に抑えつつオーバーフローを防ぐため、タイムスタンプは固定長ではなく、全体のビット長の4分の1を占めます。
つまり、全体のビット長を増やすだけでタイムスタンプも長くなり、より長い期間にわたって使い続けられます。

ただしトレードオフとして、ビット長を増やすとタイムスタンプ部分に不要な先頭のゼロが増えます。

## 名前の由来
"Four" は、タイムスタンプがビット長の1/4を占めることに由来します。
また、英単語の "Forward" にちなんだ言葉遊びでもあります。

## 仕様
FWIDは、次のようなバイト配列(ビッグエンディアン)で表現されます。

```
[ (全体のビット数 / 4) ビットのタイムスタンプ ] + [ (全体のビット数 / 4 * 3) ビットのCSPRNG出力 ]
```

タイムスタンプは2001-01-01 00:00:00 UTCからの経過時間(ミリ秒)です。

例えば、全体のビット長が256ビットの場合、タイムスタンプは64ビット、ランダム部分は192ビットになります。

比率を固定しているのは、IDからタイムスタンプを取り出す際に、区切り文字を使わなくても正確な長さを簡単に判断できるようにするためです。

## フォーマット
他の方式と異なり、FWIDは複数のフォーマットを提供します。

### 標準テキスト

テキスト変換にはBase32 Hexの派生方式を使います。

ただし、パディング文字には "=" ではなく "Z" を使います。これにより、ほとんどの場所で利用できます。

### 可読テキスト

文字エンコーディングにCrockford's Base32を使い、人間が読みやすいよう次の規則を設けています。

- 文字セットはCrockfordの小文字のアルファベット(`0-9, a-z` から `i`、`l`、`o`、`u` を除いたもの)です。見間違えやすい文字を避けられます
- パディングはありません。データが埋まらない場合、最後のグループは短くなります
- 8文字ごとにハイフン(`-`)を挿入します
- パース時は `i` と `l` を `1` として、`o` を `0` として読みます。標準テキストと混同しないよう、大文字は拒否します
- Crockford's Base32のチェックシンボルは使用しません

### コンパクトテキスト

文字セットにBase62(`0-9A-Za-z`)を使います。
バイト配列をビッグエンディアンの多倍長整数(任意精度整数)として解釈し、Base62に変換します。
同じビット長であれば常に固定長の出力になるよう、先頭を `0` でゼロ埋めします。

標準テキスト形式と比べると、256bitにおける長さは約76%(標準テキスト形式では56文字、コンパクトでは43文字)です。

なお、Base62は2のべき乗ではないため、ビット演算は使えず、デコードには多倍長整数の演算が必要です。
また、大文字と小文字を区別しない環境では使用できません。

## 使用上の注意

- 同一タイムスタンプでの順序保証はありません。つまり、同一ミリ秒内で複数回生成した場合、それらの順序はランダムです。もし同一ミリ秒内での順序保証が必要な場合、ランダム部の先頭部分を連番に変える必要がありますが、そのための仕様はFWID自身の仕様には含まれていません。
- エポックは2001-01-01 00:00:00 UTC固定であり、TSIDやSnowflake系のようにエポックの変更で寿命を延ばすようなことはできません。代わりにビット幅を増やす必要があります。
- 異なるビット幅のID同士で時系列順でのソートはできません。異なるビット幅のIDが含まれる場合、一度デコードしてタイムスタンプを取り出し比較する必要があります。

## 衝突確率
タイムスタンプが異なるIDが衝突することはありません。以下の数値は最悪のケース(すべてのIDが同一ミリ秒内に生成される場合)を表します。値は誕生日の確率の近似 n ≈ √(2·2^r·p)(50%の場合: n ≈ 1.1774·√2^r)で求めています。r はランダム部分のビット幅です。

| ビット数 | ランダム部分のビット幅 | 衝突確率10⁻¹⁸となるID数 | 衝突確率10⁻⁹となるID数 | 衝突確率50%となるID数 |
|---------:|-----------------------:|:------------------------|:-----------------------|:----------------------|
|      128 |                     96 | 4.0×10⁵                 | 1.3×10¹⁰               | 3.3×10¹⁴              |
|      160 |                    120 | 1.6×10⁹                 | 5.2×10¹³               | 1.4×10¹⁸              |
|      192 |                    144 | 6.7×10¹²                | 2.1×10¹⁷               | 5.6×10²¹              |
|      256 |                    192 | 1.1×10²⁰                | 3.5×10²⁴               | 9.3×10²⁸              |
|      384 |                    288 | 3.2×10³⁴                | 1.0×10³⁹               | 2.6×10⁴³              |
|      512 |                    384 | 8.9×10⁴⁸                | 2.8×10⁵³               | 7.4×10⁵⁷              |

## オーバーフローの時期
各ビット長は、次の時期にオーバーフローします。

| ビット数 | タイムスタンプのビット幅 | 最大秒数                   | オーバーフローの時期(概算)                                 |
|---------:|-------------------------:|:---------------------------|:-----------------------------------------------------------|
|      128 |                       32 | 4,294,967        (≈49.7日) | `2001-02-19T17:02:47.296+00:00` (すでにオーバーフロー済み) |
|      160 |                       40 | 1,099,511,627    (≈34.8年) | `2035-11-04T19:53:47.776+00:00`                            |
|      192 |                       48 | 281,474,976,710 (≈8,920年) | `10920-08-03T05:31:50.656+00:00`                           |
|      256 |                       64 | 1.8×10¹⁶                   | エポックから約5.8×10⁸年後                                  |
|      384 |                       96 | 7.9×10²⁵                   | エポックから約2.5×10¹⁸年後                                 |
|      512 |                      128 | 3.4×10³⁶                   | エポックから約1.1×10²⁸年後                                 |
