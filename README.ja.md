# FWID (FourWord Identifier)
時系列でソート可能な、新しいランダム識別子の生成方式です。

## 概要
ランダムな識別子を生成するための新しい方式です。
データベースの主キーなどの用途を想定して設計されています。

衝突の可能性を最小限に抑えつつオーバーフローを防ぐため、タイムスタンプは固定長ではなく、全体のビット長の4分の1を占めます。
つまり、全体のビット長を増やすだけでタイムスタンプも長くなり、より長い期間にわたって使い続けられます。

ただし、その代償として、ビット長を増やすとタイムスタンプ部分に不要な先頭のゼロが増えます。

## 名前の由来
"Four" は、タイムスタンプがビット長の1/4を占めることに由来します。
また、"Forward" という単語にちなんだ言葉遊びでもあります。

## 仕様
FWIDは、次のようなバイト配列(ビッグエンディアン)で表現されます。

```
[ (全体のビット数 / 4) ビットのUNIXタイムスタンプ (UTC, ミリ秒) ] + [ (全体のビット数 / 4 * 3) ビットのCSPRNG (暗号論的擬似乱数生成器) の出力 ]
```

例えば、全体のビット長が256ビットの場合、タイムスタンプは64ビット、ランダム部分は192ビットになります。

比率を固定しているのは、IDからタイムスタンプを取り出す際に、区切り文字を使わなくても正確な長さを簡単に判断できるようにするためです。

## フォーマット
他の方式と異なり、FWIDは複数のフォーマットを提供します。

### 標準テキスト

テキスト変換にはBase32 Hexの派生方式を使います。

ただし、パディング文字には "=" ではなく "Z" を使います。これにより、ほとんどの場所で利用できます。

### 可読テキスト

標準テキストをもとに、人間が読みやすいよう次の変更を加えたものです。

- 文字セットを小文字にします(`0-9, A-V` → `0-9, a-v`)
- 8文字ごとにハイフン(`-`)を挿入します

### コンパクトテキスト

文字セットにBase62(`0-9A-Za-z`)を使います。
バイト配列をビッグエンディアンの多倍長整数(任意精度整数)として解釈し、Base62に変換します。
同じビット長であれば常に固定長の出力になるよう、先頭を `0` でゼロ埋めします。

長さはテキスト形式の約76%です。
例えば256ビットの場合、テキスト形式は56文字ですが、コンパクトテキストは43文字に収まります。

なお、Base62は2のべき乗ではないため、ビット演算は使えず、デコードには多倍長整数の演算が必要です。
また、大文字と小文字を区別しない環境では使用できません。

## 衝突確率

| ビット数 | ランダム部分のビット幅 | 衝突確率10⁻¹⁸となるID数 | 衝突確率10⁻⁹となるID数 | 衝突確率50%となるID数 |
|---:|---:|:---|:---|:---|
| 128 | 96 | 4.0×10⁵ | 1.3×10¹⁰ | 3.3×10¹⁴ |
| 160 | 120 | 1.6×10⁹ | 5.2×10¹³ | 1.4×10¹⁸ |
| 192 | 144 | 6.7×10¹² | 2.1×10¹⁷ | 5.6×10²¹ |
| 256 | 192 | 1.1×10²⁰ | 3.5×10²⁴ | 9.3×10²⁸ |
| 384 | 288 | 3.2×10³⁴ | 1.0×10³⁹ | 2.6×10⁴³ |
| 512 | 384 | 8.9×10⁴⁸ | 2.8×10⁵³ | 7.4×10⁵⁷ |
